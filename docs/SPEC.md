## 0. 本規格書的地位

1. **SPEC.md 是本專案的最高標準。** 所有人和所有 AI agent 都要依照它做事。
2. 程式和規格不一致時，**以規格為準**，去改程式。
3. 想改變任何行為：**先改 SPEC.md**，在「§10 變更紀錄」寫一行，然後才改程式。
4. 規格沒寫到的細節: 先跟使用者討論，不要自己腦補。
5. 不准加入「§9 範圍外」列出的功能，除非先改規格。

### 文件分工與優先順序

| 優先 | 文件 | 回答什麼 |
|---|---|---|
| 1 | `SPEC.md` | **做什麼**：功能、規則、資料格式、驗收標準。 |
| 2 | `ARCHITECTURE.md` | **怎麼組織**：檔案結構、每個檔案負責什麼、檔案之間怎麼互動。 |
| 3 | `PLAN.md` | **照什麼順序做**：實作步驟、每一步做完怎麼檢查。 |

- 下層文件不可以和上層矛盾。發現矛盾時，**以上層為準**，並回報使用者。
- SPEC.md 只寫「做什麼」，不規定檔案怎麼切。檔案結構一律看 ARCHITECTURE.md。

## 1. 產品概述

Stairs 是一個「**依序待辦清單**」網頁。
一個專案有很多步驟，必須照順序做：做完 A 才能做 B，做完 B 才能做 C。
前面沒完成，後面就鎖住。

### 名詞表

| 名詞 | 意思 |
|---|---|
| 專案 | 一組要依序完成的步驟，例如「寫論文」。 |
| 步驟／階 | 專案裡的一件事。第 1 階在最上面。 |
| 已完成 | 已經打勾的步驟（`done: true`）。 |
| 目前這一階 | 第一個還沒完成的步驟。**只有它可以打勾。** |
| 鎖住 | 排在「目前這一階」後面的步驟。不能打勾。 |
| 全部完成 | 專案至少有 1 個步驟，且每個步驟都已完成。 |
| 已完成專案 | 全部完成的專案。放在「已完成」分頁。其他專案（包含 0 個步驟的）都是**未完成專案**，放在「未完成」分頁。 |
| 截止日期 | 專案的期限，精確到「整點」（例如 2026/10/05 16:00）。可以不設。 |
| 完成日期 | 專案最後一次變成全部完成的時間。畫面上只顯示日期。 |

## 2. 技術限制

- **純 HTML / CSS / JavaScript。** 不用框架、不用 npm、不用建置工具。
- **不用任何外部套件或 CDN。** 必須可以離線使用。
- **雙擊 `index.html` 就能直接用**（`file://` 開啟）。
- 用一般 `<script src="...">` 載入，**不用 ES module**（`file://` 下 module 會被瀏覽器擋）。
- 支援最新版 Chrome、Edge、Firefox、Safari，桌機和手機都要能用。

- **資料邏輯和畫面要分開**：改資料只能透過 §7 的函式，畫面程式不可以直接改 state 物件。
- 檔案結構和每個檔案的分工：見 **`ARCHITECTURE.md`**。

## 3. 資料模型

### 3.1 結構

```json
{
  "version": 1,
  "activeProjectId": "p_lx3k9a_4f2b1c",
  "projects": [
    {
      "id": "p_lx3k9a_4f2b1c",
      "name": "寫論文",
      "createdAt": 1700000000000,
      "deadline": "2026-10-05T16:00",
      "completedAt": null,
      "steps": [
        { "id": "s_lx3kab_9d0e2f", "title": "找題目", "done": true },
        { "id": "s_lx3kac_1a2b3c", "title": "讀文獻", "done": false }
      ]
    }
  ]
}
```

| 欄位 | 型別 | 規則 |
|---|---|---|
| `version` | number | 固定為 `1`。 |
| `activeProjectId` | string 或 `null` | 目前打開的專案。沒有專案時為 `null`。 |
| `projects` | array | 專案順序 = 建立順序（新的放最後）。畫面上的排序見 F9、F10，**不改**這個陣列的順序。 |
| `id` | string | 專案用 `p_` 開頭，步驟用 `s_` 開頭。產生方式：前綴 + `Date.now().toString(36)` + `_` + `Math.random().toString(36).slice(2, 8)`。 |
| `name` / `title` | string | 去掉頭尾空白後不可為空。專案名最長 100 字，步驟名最長 200 字（超過就截斷）。 |
| `createdAt` | number | 建立時間（毫秒）。 |
| `deadline` | string 或 `null` | 截止日期，當地時間，格式 `YYYY-MM-DDTHH:MM`（例如 `"2026-10-05T16:00"`）。沒設為 `null`。建立時設定或跳過（F8）。 |
| `completedAt` | number 或 `null` | 完成時間（毫秒）。規則見 §3.2 第二條。新專案為 `null`。 |
| `done` | boolean | 是否已完成。 |

### 3.2 核心規則（不變式）⚠️

> **已完成的步驟，一定是「從第 1 階開始、連續的一段」。**

- 合法：`✓ ✓ ✓ □ □`
- 不合法：`✓ □ ✓ □ □`（第 3 階完成但第 2 階沒完成）

所有操作做完後，這條規則都必須成立。**任何會打破它的程式都是 bug。**

由此推出：
- 「目前這一階」= 第一個 `done: false` 的步驟的位置。
- 沒有未完成步驟時，沒有「目前這一階」。

> **第二條：`completedAt` 有值（數字），若且唯若專案全部完成。**

- 專案從「未完成」變成「全部完成」的那一刻（打勾、刪除步驟都算）→ `completedAt` 設成當下時間。
- 本來就全部完成、操作後仍然全部完成（例如改名、改截止日期）→ `completedAt` 不變。
- 專案不再是全部完成（取消打勾、新增步驟、刪到剩 0 步）→ `completedAt` 設成 `null`。

### 3.3 儲存

- 存在瀏覽器 `localStorage`，key 是 **`stairs.v1`**，內容是上面 JSON 的字串。
- **每次資料改動後立刻存檔。**
- 讀取時：
  - 沒有資料 → 用空資料 `{ version: 1, activeProjectId: null, projects: [] }` 啟動。
  - 最外層壞掉（JSON 壞掉、不是物件、`version` 不是 `1`、`projects` 不是陣列）→ 用空資料啟動，**不可以當掉**，並在 console 印出警告。
  - 只有單一專案或步驟壞掉 → **只丟掉那一筆**，其他保留，並在 console 印出警告。
    - 「壞掉」是指：不是物件、`id` 不是字串、名稱去掉頭尾空白後是空的（或不是字串）、`done` 不是 `true`/`false`、`steps` 不是陣列、`createdAt` 不是數字。
    - 名稱太長**不算**壞掉，照 §3.1 截斷。
  - 資料違反不變式 → 自動修正：從第一個未完成的步驟開始，後面全部設成未完成。
  - `deadline` 沒有、不是字串、格式不對、或不是真的日期（例如 2 月 30 日）→ 設成 `null`，**不丟掉**專案。
  - `completedAt` 照 §3.2 第二條修正，**不丟掉**專案：
    - 專案沒有全部完成 → 設成 `null`。
    - 專案全部完成，但 `completedAt` 不是數字（例如 v1.5 以前的舊資料）→ 設成讀取當下的時間。
  - `activeProjectId` 指向不存在的專案 → 改成第一個專案的 id（沒專案則 `null`）。
- `localStorage` 不能用（例如被瀏覽器封鎖）→ 程式照常運作，只是不會存，畫面上方顯示一行提示「無法儲存，重新整理後資料會消失」。

## 4. 功能規格

### F1. 多個專案

- **新增**：輸入專案名 → 按「新增」或 Enter → 跳出日期時間選單（F8「建立專案時」），設定或跳過截止日期後才真正建立。
  - 名稱去掉頭尾空白後是空的 → 不跳選單，什麼都不做。
  - 建立後輸入框清空，並**自動切換過去**。如果正在看「已完成」分頁，自動切回「未完成」分頁（F10），讓新專案看得到。專案在清單裡的位置見 F9。
- **切換**：點專案清單裡的專案。
- **改名**：見 F7。
- **刪除**：見 F7。

### F2. 步驟：新增與拖曳排序

- **新增**：在步驟清單下方輸入框輸入標題 → 按「新增」或 Enter。
  - 新步驟一律加在**最後面**，狀態為**未完成**。
  - 新增後輸入框清空、保持焦點，方便連續新增。
  - 如果專案原本已全部完成，加了新步驟後就變回未完成，新步驟成為「目前這一階」。
- **拖曳換順序**：
  - **沒有拖曳把手**，直接按住步驟拖。勾選框、按鈕、改名中的輸入框上按下去**不會**開始拖，它們照原本的功能運作。
  - **滑鼠**：在步驟上按住，移動超過約 5px 才開始拖。沒移動就放開 = 普通點擊，什麼都不會發生（雙擊名稱改名照常）。
  - **手機觸控**：在步驟上**長按約 0.4 秒**、手指沒有移動，才開始拖；開始時步驟要有「被拿起來」的視覺提示。長按前手指就移動 → 照常捲動頁面，不拖。拖曳中頁面不捲動。長按不可以跳出瀏覽器的選取文字或選單。
  - **已完成的步驟不能拖**（在它上面按住不會開始拖）。
  - **未完成的步驟只能在未完成區裡換位置**，不能拖進已完成區。
  - 這樣排序後，不變式一定成立。
  - 拖曳後，排在未完成區第一個的步驟就是新的「目前這一階」。
  - 用 **Pointer Events** 實作，滑鼠和手機觸控都能拖。
  - 拖曳時要有視覺提示：被拖的項目半透明，放下的位置有一條線。
- **鍵盤排序**：焦點在某個未完成步驟裡的任何控制項（勾選框、✏️、🗑️）上時，按 **Alt+↑ / Alt+↓**（Mac 是 Option+↑ / Option+↓）把它上移／下移一格。規則和拖曳相同（不能移進已完成區、不能超出清單；不能移時什麼都不做）。移動後焦點留在同一個步驟的同一個控制項上；例外：焦點在勾選框上、而移動後它變成鎖住（勾選框 disabled）時，焦點改到同一個步驟的 ✏️。畫面上**沒有** ↑↓ 按鈕。

### F3. 鎖定

每個步驟依狀態顯示：

| 狀態 | 勾選框 | 外觀 |
|---|---|---|
| 已完成 | 已勾、可按（用來取消，見 F6） | ✓、標題有刪除線、顏色變淡 |
| 目前這一階 | 未勾、可按 | 正常顏色、**醒目標示**（例如左邊色條或外框） |
| 鎖住 | 未勾、**disabled** | **灰色**、顯示 **🔒**、滑鼠移上去提示「需先完成上一階」 |

### F4. 打勾自動解鎖

- 打勾「目前這一階」→ 它變成已完成 → 下一階**自動**變成「目前這一階」（解鎖）。
- 不需要任何確認。
- 對鎖住的步驟打勾：不會發生（勾選框是 disabled）；就算程式被呼叫，資料也**不變**。

### F5. 全部完成的慶祝畫面

- **時機**：打勾讓專案從「未完成」變成「全部完成」的**那一刻**。
- **內容**：一個小的置中彈窗，有：
  - 純 CSS 彩帶／紙屑動畫（不用外部套件，約 2 秒）。
  - 文字：「🎉 全部完成！」和專案名稱。
  - 專案有截止日期時，多一行灰色小字：「如果加過行事曆，記得到行事曆刪掉這個截止事件。」（網頁沒辦法自己刪行事曆裡的事件，見 F11、§9。）沒有截止日期就不顯示。
  - 一個「關閉」按鈕。按 Esc 或點彈窗外面也能關閉。
- **不重複跳**：
  - 重新整理頁面、切換專案、再切回來，**都不會**再跳。
  - 取消打勾後再重新全部完成 → 會再跳一次（因為又發生了「從未完成變成全部完成」）。
- 0 個步驟的專案**不算**完成，不跳慶祝。
- 使用者系統設定「減少動態效果」（`prefers-reduced-motion`）時，不播動畫，只顯示文字。

### F6. 取消打勾（連帶退回）

- 已完成的步驟可以點勾選框取消。
- **規則**：取消第 i 階 → 第 i 階**和它後面所有步驟**都變成未完成。
- 第 i 階變成新的「目前這一階」。
- **確認**：
  - 如果只會退回它自己（它是最後一個已完成的）→ 直接取消，不確認。
  - 如果會連帶退回其他步驟 → 先跳確認：「取消這一階，後面 N 個已完成的步驟也會一起退回。確定嗎？」按取消就什麼都不改。

### F7. 改名與刪除

**改名**（專案和步驟都一樣）：
- 點鉛筆按鈕（✏️）或雙擊名稱 → 名稱變成輸入框，文字全選。
- Enter 或離開輸入框 → 儲存。
- Esc → 取消，恢復原名。
- 去掉頭尾空白後是空的 → 不存，恢復原名。
- 改名**不影響**完成狀態。

**刪除步驟**：
- 點垃圾桶按鈕（🗑️）→ 直接刪除，不確認。
- 刪除後不變式仍成立（不需特別處理）。
- 刪掉「目前這一階」→ 下一個未完成的步驟自動變成目前這一階。
- 刪除後如果剩下的步驟全部已完成（且至少 1 個），**不跳**慶祝畫面（慶祝只由打勾觸發）。

**刪除專案**：
- 點垃圾桶按鈕 → 跳確認：「確定要刪除專案「名稱」嗎？裡面的 N 個步驟也會一起刪掉。」
- 刪掉的是目前打開的專案 → 自動切到清單中的下一個專案；沒有下一個就切到上一個；都沒有就變成 `null`。（「清單」指 `projects` 陣列的順序，不是畫面上的排序。）

### F8. 截止日期

- 每個專案可以設一個截止日期（日期＋整點），也可以不設。
- **建立專案時**：F1 按下新增後跳出日期時間選單，按鈕是「取消」「跳過」「完成」。
  - 完成 → 建立專案，截止日期是選中的日期和小時。
  - 跳過 → 建立專案，沒有截止日期。
  - 取消、Esc、點彈窗外面 → **不建立**專案，輸入框裡的名稱保留。
  - 選單關閉後，焦點回到新增專案輸入框。
- **之後修改**：畫面中間的專案名稱下方有一顆按鈕：
  - 沒設時顯示「設定截止日期」。
  - 有設時顯示「截止 2026/10/05 16:00」。
  - 點它 → 打開日期時間選單。
- **日期時間選單**（仿 iPhone 內建的樣子，自己做，不用瀏覽器內建的日期輸入框）：
  - 是一個置中的彈窗，和確認視窗、慶祝彈窗共用同一套 dialog 做法（§6）。
  - **月曆**：
    - 最上面一行左邊是「2026年10月」，右邊是「‹」「›」兩顆按鈕，切換上一個月、下一個月。
    - 下面一行是「週日 週一 … 週六」，週日在最左邊。
    - 再下面是那個月的日期格子；1 號要排在正確的星期底下。
    - 選中的日期是**橘色實心圓**，數字顏色和主要按鈕的文字相同（對比度至少 4.5:1，§5.3；深色模式是深色字）。今天（還沒被選中時）用橘色字標示。
    - 過去的日期也可以選。
  - **時間滾輪**：
    - 在月曆下方，只有一個「小時」滾輪，**24 小時制**，每格一小時：`00:00`、`01:00`、…、`23:00`。
    - 上下滑動會停在某一格上（吸附），中間那格有一條淡色的橫條標示「選中」。離中間越遠的格子越淡。
    - 滾輪頭尾不循環：`00:00` 上面、`23:00` 下面是空的。
  - **按鈕**（之後修改時）：「取消」「完成」；已經有截止日期時，多一顆「清除」。（建立專案時的按鈕見上面。）
    - 完成 → 存成選中的日期和小時。
    - 清除 → 截止日期變成 `null`。
    - 取消、Esc、點彈窗外面 → 什麼都不改。
  - **打開時預設選中**：
    - 已有截止日期 → 選中它，月曆停在它那個月。
    - 沒有 → 選中「現在的下一個整點」，例如 14:20 打開 → 今天 15:00；23:30 打開 → 明天 00:00。
- 截止日期過了**不變色**；Stairs 自己**不跳提醒**，提醒用 F11 交給行事曆（§9）。
- 截止日期不影響步驟、打勾、完成狀態。

### F9. 未完成專案的排序與分組

只用在專案列表的「未完成」分頁（F10）。

- **排序**：
  - 有截止日期的專案在前面，照截止日期由早到晚排。
  - 沒有截止日期的專案在最後面，照建立順序。
  - 截止日期完全相同的，照建立順序。
- **分組**：同一天截止的專案是一組。每組上面有一行**灰色小字的分隔線**，日期在中間、兩邊是橫線，例如：
  ```
  ──────── 2026/10/05 ────────
  ```
  - 沒有截止日期的那組，分隔線文字是「無截止日期」。
  - 如果清單裡**全部**專案都沒有截止日期，就不顯示任何分隔線。
- 專案的截止日期改了，清單立刻重新排序。
- 分隔線只是標示，不能點、不能拿到焦點。

### F10. 未完成／已完成分頁

- **切換欄位**：放在專案列表（F12）的**最下面**，兩格並排：左邊「未完成」、右邊「已完成」。專案很多、列表要捲動時，切換欄位仍固定在列表底部看得到。
  - iPhone 上要避開最下面的橫條（安全區域），不被它擋住。
  - 外觀：一條圓角膠囊形的底，選中的那格是一塊凸起的圓角色塊（淺色模式白色、深色模式比底亮一點的灰色），文字比較深；沒選中的那格文字比較淡。
  - 切換時，凸起的色塊**滑**到另一格（約 0.2 秒；「減少動態效果」時直接跳過去）。
  - 每次打開網頁都從「未完成」開始；目前在哪個分頁**不存檔**。
- **未完成分頁**：顯示所有未完成專案，排序和分組照 F9。
- **已完成分頁**：
  - 顯示所有已完成專案，照完成日期**新的在上面**；完成時間完全相同的，照建立順序。
  - 每個專案名稱是**灰色**的，名稱下面有一行灰色小字「完成於 2026/10/05」（只有日期，沒有時間）。
  - 沒有日期分隔線。
- **專案自動移動**：
  - 專案變成全部完成（打勾最後一階、刪掉最後一個未完成步驟）→ 移到已完成分頁。
  - 已完成專案取消打勾或新增步驟 → 回到未完成分頁，`completedAt` 清掉。
  - 移動時，**畫面中間打開的專案不變**，列表的分頁也不會自動切換；它只是從目前分頁的清單裡消失（或出現）。
- **打開的專案**：可以打開任何一個專案，不管它在哪個分頁。打開已完成專案時，畫面中間照常顯示，所有操作照常可用（取消打勾、新增步驟、改名、刪除、截止日期）。打開的專案只有在**目前分頁看得到它**時，左邊清單才醒目標示它。
- **空的分頁**：
  - 未完成分頁沒有專案 → 「沒有未完成的專案。」
  - 已完成分頁沒有專案 → 「還沒有完成的專案。」

### F11. 加入行事曆（截止前 24 小時提醒）

Stairs 自己不跳通知（沒有伺服器，見 §9）。提醒交給手機或電腦的**行事曆 App**：Stairs 產生一個行事曆檔（`.ics`），使用者把它加進行事曆，由行事曆在截止前 24 小時提醒。

- **按鈕**：專案有截止日期時，截止日期按鈕（F8）旁邊多一顆「加入行事曆」按鈕。沒有截止日期時不顯示。
- **按下去** → 下載一個 `.ics` 檔，檔名是「專案名稱.ics」（檔名不能用的字元換成 `_`）。不需要確認。
  - iPhone Safari 會直接問要不要加入行事曆；電腦上下載後雙擊打開。這一步之後由瀏覽器和行事曆 App 處理，Stairs 不管。
- **檔案內容**：一個事件。
  - 標題：「截止：專案名稱」。
  - 時間：從截止時間開始、長度 0（一個時間點）。用**當地時間**，不帶時區，和 `deadline` 一樣（§3.1）。
  - 提醒：截止前 **24 小時**跳通知，通知文字「「專案名稱」明天這個時候截止」。
  - 備註：「來自 Stairs」。
  - 每個專案有固定的事件 id（由專案 id 產生），同一個專案每次產生的 id 都一樣。
- **不會自動同步**：
  - 之後在 Stairs 改截止日期、改名、刪除專案、完成專案，行事曆裡的事件**都不會跟著變**。
  - 改了截止日期要再按一次「加入行事曆」；舊的事件要使用者自己在行事曆裡刪掉。
  - 按鈕的提示文字（`title`）要寫出這件事：「下載行事曆檔，截止前 24 小時提醒。之後改截止日期要重新加入。」
- 截止時間已經在 24 小時內或已經過了，仍然可以下載（行事曆可能不會再提醒，Stairs 不另外處理）。
- 已完成的專案只要有截止日期，按鈕照樣顯示。
- 資料不變：按這顆按鈕不改任何 state，也不存檔。

### F12. 隱藏式專案列表

畫面中間只放目前打開的專案。專案列表平常**收起來**，需要時才從左邊滑出來（電腦和手機都一樣）。

- **列表裡有什麼**（由上到下）：Stairs 標題和「✕ 關閉」按鈕、專案清單（F9、F10）、新增專案輸入框、未完成／已完成切換欄位（F10）。
- **打開**：
  - 畫面**左下角**固定一顆 **≡（三條橫線）** 按鈕，點它打開。它不會蓋住內容：頁面最下面要留出它的空間，iPhone 上避開最下面的橫條。
  - **從螢幕左邊緣往右滑**：手指從最左邊約 24px 以內開始，往右滑超過約 60px、而且主要是橫向移動 → 打開。從其他地方開始的滑動不算，也不影響步驟拖曳（F2）和頁面捲動。
  - 注意：在 iPhone **Safari 分頁**裡，左邊緣右滑是 Safari 的「上一頁」，可能會被 Safari 搶走；從主畫面打開的 App 沒有這個問題。≡ 按鈕任何時候都能用。
- **外觀**：
  - 從左邊滑出（約 0.2 秒；「減少動態效果」時直接出現），寬度約 300px，手機上最多畫面寬度的 85%。
  - 列表後面的頁面蓋一層半透明的暗色，表示不能操作。
- **關閉**：
  - 點 ✕、按 Esc、點列表外面的暗色區域、在列表上往左滑超過約 60px。
  - **選了一個專案** → 打開那個專案，並關閉列表。
  - **建立了新專案**（F1、F8 按完成或跳過）→ 打開新專案，並關閉列表。在日期時間選單按取消 → 列表保持打開。
- **狀態不存檔**：每次打開網頁，列表都是收起來的。
- 打開確認視窗、日期時間選單、慶祝彈窗時，它們蓋在列表上面。

- 畫面中間：目前打開的專案，水平置中、有最大寬度。專案名稱（可改名、刪除）、截止日期按鈕（F8）和加入行事曆（F11）、進度、步驟清單、新增步驟輸入框。

- 電腦和手機用同一種版面；手機寬度（< 640px）時邊距比較小。按鈕觸控區至少 40×40px。

### 5.2 空狀態

- 沒有任何專案 → 畫面中間顯示：「還沒有專案。點左下角的 ≡ 打開專案列表，建立你的第一個專案吧！」
- 專案沒有步驟 → 步驟區顯示：「這個專案還沒有步驟。在下面新增第一階。」

### 5.3 風格

- 介面文字一律**繁體中文**。
- 乾淨、簡單、留白充足。
- 支援**深色模式**，跟隨系統設定（`prefers-color-scheme`）。
- 顏色用 CSS 變數定義在 `:root`。
- 主色是**橘色**。淺色模式用米白底；深色模式用接近黑色的底。按鈕上的文字和背景要看得清楚（對比度至少 4.5:1）。
- **圖示用線條圖示**（自己畫的 SVG，不用 emoji、不用外部圖示庫）。本規格裡寫的 ✏️、🗑️、🔒、‹、› 是指「這個位置有這個意思的按鈕或標示」，畫面上用對應的線條圖示呈現。慶祝彈窗標題的 🎉 保留 emoji。
- **步驟排成階梯狀**：越後面的步驟往右縮排越多，像一階一階的樓梯。**縮排到第 3 階為止**：第 1 階不縮排、第 2 階縮 1 格、第 3 階和後面所有步驟都縮 2 格。手機寬度時每格縮排比桌機小，但要是 v1.5 手機縮排的 **1.5 倍**，標題仍要有足夠寬度。
- 階梯狀不改變任何操作規則：順序、拖曳、鍵盤排序、打勾都和 F2–F4 相同。
- **App 圖示**：黑底、橘色階梯（和畫面左上角 Stairs 旁邊的圖案相同）。用專案裡的一張 180×180 PNG，同時當瀏覽器分頁的小圖示和 iPhone「加入主畫面」的圖示，主畫面名稱是「Stairs」。
- **動畫**：操作後的畫面變化用短動畫（約 0.2 秒）呈現：排序時步驟滑到新位置、新增的步驟淡入、刪除的步驟淡出、打勾時勾勾彈一下、下一階解鎖時亮一下、進度條長長、彈窗淡入。
  - 專案在分頁之間移動、或因截止日期改變而重新排序時，專案列表裡的專案也用同樣的短動畫滑動／淡入淡出。
  - 系統開啟「減少動態效果」（`prefers-reduced-motion: reduce`）時，不播放這些動畫。
  - 瀏覽器不支援時沒有動畫，功能完全不受影響。
  - 動畫不能擋住操作：動畫進行中仍可以點按、打字；焦點規則和 §6 相同。

## 6. 無障礙

- 所有只有圖示的按鈕都要有 `aria-label`（例如「刪除步驟：找題目」）。
- 全部功能都能**只用鍵盤**操作（Tab、Enter、空白鍵、Esc；排序用 Alt+↑ / Alt+↓，見 F2）。
- 未完成步驟裡的控制項要用 `aria-keyshortcuts` 告訴螢幕閱讀器可以用 Alt+↑ / Alt+↓ 排序。
- **日期時間選單**：
  - 月曆：焦點在日期格子上時，方向鍵移動一天（左右）或一週（上下），跨月時月曆跟著換月；Enter 或空白鍵選中。‹ › 是一般按鈕。
  - 時間滾輪：拿到焦點後，↑ / ↓ 換一小時；用 `role="spinbutton"` 和 `aria-valuenow`、`aria-valuetext`（例如「16 點」）。
  - 打開時焦點在選中的日期格子上；關閉後焦點回到打開它的地方（截止日期按鈕，或建立專案時的新增專案輸入框）。例外：建立專案按完成或跳過後列表會關閉，焦點照「專案列表」那條規則去新增步驟輸入框。
- **專案列表（F12）**：
  - ≡ 按鈕 `aria-label="打開專案列表"`、`aria-expanded` 表示列表開關、`aria-controls` 指向列表。
  - 列表打開時當成對話框：`role="dialog"`、`aria-modal="true"`、`aria-label="專案列表"`，後面的頁面不能點、Tab 不會跑到後面。
  - 打開時焦點移到目前打開的專案（列表裡看不到它時，移到新增專案輸入框）。
  - 關閉後焦點：選了專案或用 ✕／Esc／點外面關閉 → 回到 ≡ 按鈕；建立新專案 → 新增步驟輸入框。
- **未完成／已完成切換欄位**：用 `role="tablist"`，兩格是 `role="tab"`，選中的那格 `aria-selected="true"`；← → 方向鍵在兩格之間切換。
- 勾選框用真正的 `<input type="checkbox">` 或有正確 role 的元素。
- 鎖住的步驟：勾選框 `disabled`，並用 `aria-describedby` 或 `title` 說明「需先完成上一階」。
- 慶祝彈窗用 `role="dialog"`、`aria-modal="true"`，開啟時焦點移到「關閉」按鈕，關閉後焦點回到原本位置。

## 7. 資料操作函式介面

這些函式放在哪個檔案、怎麼讓畫面呼叫：見 `ARCHITECTURE.md`。

**規則：**
- 除了 `load` / `save`，全部是**純函式**：輸入舊 state，回傳**新的** state，**不修改**傳進來的物件。
- 每個函式做完，不變式（§3.2 兩條）都必須成立。會改步驟的函式要照 §3.2 第二條順便更新 `completedAt`。
- 不合法的操作（找不到 id、勾鎖住的步驟、名稱空白、移到不允許的位置…）→ **直接回傳原本的 state**，不丟錯誤。

| 函式 | 說明 |
|---|---|
| `emptyState()` | 回傳空資料。 |
| `load()` | 從 localStorage 讀取並驗證／修正（§3.3），回傳 state。 |
| `save(state)` | 存進 localStorage。失敗時回傳 `false`，成功回傳 `true`。 |
| `createProject(state, name, deadline)` | 新增專案並設為 active。`deadline` 規則同 `setDeadline`；沒傳或 `null` → 沒有截止日期；格式不對 → 不變（不建立）。 |
| `renameProject(state, projectId, name)` | 改專案名。 |
| `deleteProject(state, projectId)` | 刪專案，並依 F7 規則調整 `activeProjectId`。 |
| `setActiveProject(state, projectId)` | 切換專案。 |
| `addStep(state, projectId, title)` | 在最後新增未完成步驟。 |
| `renameStep(state, projectId, stepId, title)` | 改步驟名。 |
| `deleteStep(state, projectId, stepId)` | 刪步驟。 |
| `moveStep(state, projectId, stepId, toIndex)` | 把未完成步驟移到 `toIndex`（移動後的位置）。已完成步驟或目標在已完成區 → 不變。 |
| `checkStep(state, projectId, stepId)` | 只有「目前這一階」能成功打勾。 |
| `uncheckStep(state, projectId, stepId)` | 取消該步驟和後面所有步驟。 |
| `getCurrentStepIndex(project)` | 回傳目前這一階的位置；沒有則回傳 `-1`。 |
| `countDone(project)` | 回傳已完成數。 |
| `isProjectComplete(project)` | 至少 1 步且全部完成 → `true`。 |
| `setDeadline(state, projectId, deadline)` | 設定截止日期。`deadline` 是 `YYYY-MM-DDTHH:MM` 格式的真實日期，或 `null`（清除）。格式不對 → 不變。 |
| `listProjects(state, tab)` | `tab` 是 `"open"`（未完成）或 `"done"`（已完成）。回傳該分頁的專案陣列，已照 F9／F10 排好。不改 state。 |
| `toIcs(project)` | 回傳 F11 行事曆檔的文字內容（字串）。專案沒有截止日期 → 回傳 `null`。不改 state。 |

慶祝畫面的觸發由畫面程式判斷：`checkStep` 前 `isProjectComplete` 是 `false`、之後是 `true` → 顯示慶祝。這個狀態**不存檔**。

## 8. 驗收清單

全部打勾才算完成。每一項都要實際在瀏覽器操作過。

**基本**
- [ ] 雙擊 `index.html`，不用任何伺服器就能用。
- [ ] 斷網也能正常使用。
- [ ] 重新整理後，專案、步驟、完成狀態、目前打開的專案都還在。

**F1 專案**
- [ ] 能新增多個專案，新專案自動被打開。
- [ ] 能在專案間切換，各自的步驟和進度互不影響。
- [ ] 空白名稱無法新增。

**F2 步驟**
- [ ] 新步驟加在最後、未完成。
- [ ] 未完成步驟可以用滑鼠拖曳換順序。
- [ ] 手機（或瀏覽器觸控模擬）可以拖曳。
- [ ] 已完成步驟不能拖；未完成步驟拖不進已完成區。
- [ ] 畫面上沒有拖曳把手和 ↑↓ 按鈕。
- [ ] 滑鼠按住步驟移動就能拖；點勾選框、✏️、🗑️、雙擊名稱都照常運作，不會變成拖曳。
- [ ] 手機上長按步驟約 0.4 秒才開始拖；手指直接滑過步驟時頁面照常捲動；長按不會跳出選取文字的選單。
- [ ] Alt+↑ / Alt+↓ 可以排序，規則和拖曳相同，焦點留在同一個步驟。

**F3 / F4 鎖定與解鎖**
- [ ] 只有目前這一階能打勾。
- [ ] 後面的步驟是灰色、有 🔒、無法打勾。
- [ ] 打勾後，下一階立刻解鎖。

**F5 慶祝**
- [ ] 打勾最後一階時跳出慶祝畫面。
- [ ] 能用按鈕、Esc、點外面關閉。
- [ ] 重新整理或切換專案後不會再跳。
- [ ] 刪除步驟造成全部完成時不會跳。
- [ ] 有截止日期的專案，慶祝畫面有「記得到行事曆刪掉」那行小字；沒有截止日期的沒有。

**F6 取消打勾**
- [ ] 取消最後一個已完成步驟：直接取消，不確認。
- [ ] 取消較前面的步驟：跳確認，寫出會退回幾個；確定後它和後面全部變未完成。
- [ ] 確認視窗按取消：什麼都沒變。

**F7 改名與刪除**
- [ ] 專案和步驟都能改名；Esc 取消；空白不存。
- [ ] 能刪除步驟；刪掉目前這一階後，下一階變成目前這一階。
- [ ] 刪除專案會先確認；刪除後自動切到其他專案。

**F8 截止日期**
- [ ] 新增專案時跳出選單：完成 → 建立且有截止日期；跳過 → 建立但沒有截止日期；取消 → 不建立，名稱還在輸入框。
- [ ] 空白名稱按新增不會跳選單。
- [ ] 沒設時按鈕顯示「設定截止日期」；設好後顯示「截止 YYYY/MM/DD HH:00」。
- [ ] 月曆的 1 號排在正確的星期底下（例如 2026 年 10 月 1 日在週四）；‹ › 可以換月。
- [ ] 時間滾輪是 00:00–23:00，一格一小時，會吸附在某一格上。
- [ ] 完成、清除、取消、Esc、點外面都照 F8 運作。
- [ ] 只用鍵盤可以選日期和小時並按完成。
- [ ] 重新整理後截止日期還在。

**F9 排序與分組**
- [ ] 未完成分頁照截止日期由早到晚排，沒截止日期的在最後。
- [ ] 每一天上面有「── YYYY/MM/DD ──」灰色分隔線；沒截止日期那組是「無截止日期」；全部都沒截止日期時沒有分隔線。
- [ ] 改截止日期後清單立刻重新排序。

**F10 未完成／已完成**
- [ ] 切換欄位在專案列表最下面，左「未完成」、右「已完成」；切換時色塊會滑過去；專案很多時仍看得到；iPhone 上沒被最下面的橫條擋住。
- [ ] 打勾最後一階 → 專案從未完成分頁消失，出現在已完成分頁，名稱灰色、下面有「完成於 YYYY/MM/DD」。
- [ ] 已完成分頁新的在上面。
- [ ] 已完成專案取消打勾或新增步驟 → 回到未完成分頁。
- [ ] 在已完成分頁時新增專案 → 自動切回未完成分頁，看得到新專案。
- [ ] 重新整理後回到未完成分頁；完成日期不變。
- [ ] 舊版資料（沒有 `deadline`、`completedAt`）讀進來不會當掉，也不會丟掉任何專案。

**F11 加入行事曆**
- [ ] 有截止日期才看得到「加入行事曆」按鈕。
- [ ] 按下去下載「專案名稱.ics」；用電腦的行事曆打開，事件時間等於截止時間，提醒是 24 小時前。
- [ ] iPhone：Safari 和主畫面 App 各試一次，都能把事件加進行事曆，並在截止前 24 小時收到通知。
- [ ] 專案名稱有逗號、分號、反斜線（例如 `a,b;c\d`）或很長時，行事曆裡的標題顯示正確。
- [ ] 按這顆按鈕之後重新整理，資料沒有任何改變。

**F12 隱藏式專案列表**
- [ ] 打開網頁時列表是收起來的，畫面中間只有目前的專案；左下角有 ≡，捲到最底也沒有蓋住新增步驟輸入框。
- [ ] 點 ≡ 打開；點 ✕、按 Esc、點外面暗色區域、在列表上往左滑都能關閉。
- [ ] 手機從左邊緣往右滑能打開（主畫面 App 上試）；從畫面中間右滑、上下捲動、長按拖曳步驟都不會打開列表。
- [ ] 選一個專案 → 打開它並關閉列表；建立新專案（完成或跳過）→ 打開新專案並關閉列表；日期選單按取消 → 列表還開著。
- [ ] 列表打開時後面的頁面不能點、Tab 不會跑到後面；焦點規則照 §6。
- [ ] 電腦（1000px 寬）和手機（375px 寬）都是同一種版面，沒有橫向捲軸。

**穩定性**
- [ ] 在 DevTools 把 `localStorage["stairs.v1"]` 改成亂碼，重新整理不會當掉。
- [ ] 手動把資料改成 `✓ □ ✓`，重新整理後自動修正成 `✓ □ □`。
- [ ] 手機寬度版面正常，沒有橫向捲軸；日期時間選單和專案列表在 375px 寬放得下。
- [ ] 步驟縮排到第 3 階就停止；手機上每階縮排是原本的 1.5 倍。
- [ ] 深色模式顯示正常。
- [ ] 只用鍵盤可以完成所有操作。

## 9. 範圍外（v1 不做）

- 帳號、登入、雲端同步
- 多人協作、分享
- Stairs 自己跳的提醒、推播通知（需要伺服器；提醒改由行事曆負責，見 F11）
- 截止日期過期變色或標示
- 行事曆事件跟著 Stairs 自動更新或刪除
- 截止日期精確到分鐘；步驟的截止日期
- 日期時間選單裡點「2026年10月」切換成年／月滾輪
- 手動把專案標成完成（完成一律由打勾自動判斷）
- 子步驟、分支（不是一直線的流程）
- 匯出／匯入（F11 的行事曆檔除外）
- 復原（Undo）
- 專案的拖曳排序
