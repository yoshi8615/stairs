## 0. 本規格書的地位

1. **SPEC.md 是本專案的最高標準。** 所有人和所有 AI agent 都要依照它做事。
2. 程式和規格不一致時，**以規格為準**，去改程式。
3. 想改變任何行為：**先改 SPEC.md**，在「§10 變更紀錄」寫一行，然後才改程式。
4. 規格沒寫到的細節: 先跟使用者討論，不要自己腦補。
5. 不准加入「§9 範圍外」列出的功能，除非先改規格。

### 文件分工與優先順序

| 優先 | 文件 | 回答什麼 |
|---|---|---|
| 1 | `SPEC.md` | **做什麼**：功能、規則、資料格式、驗收標準。 |
| 2 | `ARCHITECTURE.md` | **怎麼組織**：檔案結構、每個檔案負責什麼、檔案之間怎麼互動。 |
| 3 | `PLAN.md` | **照什麼順序做**：實作步驟、每一步做完怎麼檢查。 |

- 下層文件不可以和上層矛盾。發現矛盾時，**以上層為準**，並回報使用者。
- SPEC.md 只寫「做什麼」，不規定檔案怎麼切。檔案結構一律看 ARCHITECTURE.md。

## 1. 產品概述

Stairs 是一個「**依序待辦清單**」網頁。
一個專案有很多步驟，必須照順序做：做完 A 才能做 B，做完 B 才能做 C。
前面沒完成，後面就鎖住。

### 名詞表

| 名詞 | 意思 |
|---|---|
| 專案 | 一組要依序完成的步驟，例如「寫論文」。 |
| 步驟／階 | 專案裡的一件事。第 1 階在最上面。 |
| 已完成 | 已經打勾的步驟（`done: true`）。 |
| 目前這一階 | 第一個還沒完成的步驟。**只有它可以打勾。** |
| 鎖住 | 排在「目前這一階」後面的步驟。不能打勾。 |
| 全部完成 | 專案至少有 1 個步驟，且每個步驟都已完成。 |

## 2. 技術限制

- **純 HTML / CSS / JavaScript。** 不用框架、不用 npm、不用建置工具。
- **不用任何外部套件或 CDN。** 必須可以離線使用。
- **雙擊 `index.html` 就能直接用**（`file://` 開啟）。
- 用一般 `<script src="...">` 載入，**不用 ES module**（`file://` 下 module 會被瀏覽器擋）。
- 支援最新版 Chrome、Edge、Firefox、Safari，桌機和手機都要能用。

- **資料邏輯和畫面要分開**：改資料只能透過 §7 的函式，畫面程式不可以直接改 state 物件。
- 檔案結構和每個檔案的分工：見 **`ARCHITECTURE.md`**。

## 3. 資料模型

### 3.1 結構

```json
{
  "version": 1,
  "activeProjectId": "p_lx3k9a_4f2b1c",
  "projects": [
    {
      "id": "p_lx3k9a_4f2b1c",
      "name": "寫論文",
      "createdAt": 1700000000000,
      "steps": [
        { "id": "s_lx3kab_9d0e2f", "title": "找題目", "done": true },
        { "id": "s_lx3kac_1a2b3c", "title": "讀文獻", "done": false }
      ]
    }
  ]
}
```

| 欄位 | 型別 | 規則 |
|---|---|---|
| `version` | number | 固定為 `1`。 |
| `activeProjectId` | string 或 `null` | 目前打開的專案。沒有專案時為 `null`。 |
| `projects` | array | 專案順序 = 建立順序（新的放最後）。 |
| `id` | string | 專案用 `p_` 開頭，步驟用 `s_` 開頭。產生方式：前綴 + `Date.now().toString(36)` + `_` + `Math.random().toString(36).slice(2, 8)`。 |
| `name` / `title` | string | 去掉頭尾空白後不可為空。專案名最長 100 字，步驟名最長 200 字（超過就截斷）。 |
| `createdAt` | number | 建立時間（毫秒）。 |
| `done` | boolean | 是否已完成。 |

### 3.2 核心規則（不變式）⚠️

> **已完成的步驟，一定是「從第 1 階開始、連續的一段」。**

- 合法：`✓ ✓ ✓ □ □`
- 不合法：`✓ □ ✓ □ □`（第 3 階完成但第 2 階沒完成）

所有操作做完後，這條規則都必須成立。**任何會打破它的程式都是 bug。**

由此推出：
- 「目前這一階」= 第一個 `done: false` 的步驟的位置。
- 沒有未完成步驟時，沒有「目前這一階」。

### 3.3 儲存

- 存在瀏覽器 `localStorage`，key 是 **`stairs.v1`**，內容是上面 JSON 的字串。
- **每次資料改動後立刻存檔。**
- 讀取時：
  - 沒有資料 → 用空資料 `{ version: 1, activeProjectId: null, projects: [] }` 啟動。
  - 最外層壞掉（JSON 壞掉、不是物件、`version` 不是 `1`、`projects` 不是陣列）→ 用空資料啟動，**不可以當掉**，並在 console 印出警告。
  - 只有單一專案或步驟壞掉 → **只丟掉那一筆**，其他保留，並在 console 印出警告。
    - 「壞掉」是指：不是物件、`id` 不是字串、名稱去掉頭尾空白後是空的（或不是字串）、`done` 不是 `true`/`false`、`steps` 不是陣列、`createdAt` 不是數字。
    - 名稱太長**不算**壞掉，照 §3.1 截斷。
  - 資料違反不變式 → 自動修正：從第一個未完成的步驟開始，後面全部設成未完成。
  - `activeProjectId` 指向不存在的專案 → 改成第一個專案的 id（沒專案則 `null`）。
- `localStorage` 不能用（例如被瀏覽器封鎖）→ 程式照常運作，只是不會存，畫面上方顯示一行提示「無法儲存，重新整理後資料會消失」。

## 4. 功能規格

### F1. 多個專案

- **新增**：輸入專案名 → 按「新增」或 Enter。新專案放在清單最後，並**自動切換過去**。
- **切換**：點專案清單裡的專案。
- **改名**：見 F7。
- **刪除**：見 F7。

### F2. 步驟：新增與拖曳排序

- **新增**：在步驟清單下方輸入框輸入標題 → 按「新增」或 Enter。
  - 新步驟一律加在**最後面**，狀態為**未完成**。
  - 新增後輸入框清空、保持焦點，方便連續新增。
  - 如果專案原本已全部完成，加了新步驟後就變回未完成，新步驟成為「目前這一階」。
- **拖曳換順序**：
  - 每個步驟左邊有一個拖曳把手（⋮⋮）。
  - **已完成的步驟不能拖**（沒有把手，或把手 disabled）。
  - **未完成的步驟只能在未完成區裡換位置**，不能拖進已完成區。
  - 這樣排序後，不變式一定成立。
  - 拖曳後，排在未完成區第一個的步驟就是新的「目前這一階」。
  - 用 **Pointer Events** 實作，滑鼠和手機觸控都能拖。
  - 拖曳時要有視覺提示：被拖的項目半透明，放下的位置有一條線。
- **上移／下移按鈕**：每個未完成步驟另有「↑」「↓」按鈕，規則和拖曳相同（不能移進已完成區、不能超出清單）。鍵盤使用者靠這個排序。

### F3. 鎖定

每個步驟依狀態顯示：

| 狀態 | 勾選框 | 外觀 |
|---|---|---|
| 已完成 | 已勾、可按（用來取消，見 F6） | ✓、標題有刪除線、顏色變淡 |
| 目前這一階 | 未勾、可按 | 正常顏色、**醒目標示**（例如左邊色條或外框） |
| 鎖住 | 未勾、**disabled** | **灰色**、顯示 **🔒**、滑鼠移上去提示「需先完成上一階」 |

### F4. 打勾自動解鎖

- 打勾「目前這一階」→ 它變成已完成 → 下一階**自動**變成「目前這一階」（解鎖）。
- 不需要任何確認。
- 對鎖住的步驟打勾：不會發生（勾選框是 disabled）；就算程式被呼叫，資料也**不變**。

### F5. 全部完成的慶祝畫面

- **時機**：打勾讓專案從「未完成」變成「全部完成」的**那一刻**。
- **內容**：一個小的置中彈窗，有：
  - 純 CSS 彩帶／紙屑動畫（不用外部套件，約 2 秒）。
  - 文字：「🎉 全部完成！」和專案名稱。
  - 一個「關閉」按鈕。按 Esc 或點彈窗外面也能關閉。
- **不重複跳**：
  - 重新整理頁面、切換專案、再切回來，**都不會**再跳。
  - 取消打勾後再重新全部完成 → 會再跳一次（因為又發生了「從未完成變成全部完成」）。
- 0 個步驟的專案**不算**完成，不跳慶祝。
- 使用者系統設定「減少動態效果」（`prefers-reduced-motion`）時，不播動畫，只顯示文字。

### F6. 取消打勾（連帶退回）

- 已完成的步驟可以點勾選框取消。
- **規則**：取消第 i 階 → 第 i 階**和它後面所有步驟**都變成未完成。
- 第 i 階變成新的「目前這一階」。
- **確認**：
  - 如果只會退回它自己（它是最後一個已完成的）→ 直接取消，不確認。
  - 如果會連帶退回其他步驟 → 先跳確認：「取消這一階，後面 N 個已完成的步驟也會一起退回。確定嗎？」按取消就什麼都不改。

### F7. 改名與刪除

**改名**（專案和步驟都一樣）：
- 點鉛筆按鈕（✏️）或雙擊名稱 → 名稱變成輸入框，文字全選。
- Enter 或離開輸入框 → 儲存。
- Esc → 取消，恢復原名。
- 去掉頭尾空白後是空的 → 不存，恢復原名。
- 改名**不影響**完成狀態。

**刪除步驟**：
- 點垃圾桶按鈕（🗑️）→ 直接刪除，不確認。
- 刪除後不變式仍成立（不需特別處理）。
- 刪掉「目前這一階」→ 下一個未完成的步驟自動變成目前這一階。
- 刪除後如果剩下的步驟全部已完成（且至少 1 個），**不跳**慶祝畫面（慶祝只由打勾觸發）。

**刪除專案**：
- 點垃圾桶按鈕 → 跳確認：「確定要刪除專案「名稱」嗎？裡面的 N 個步驟也會一起刪掉。」
- 刪掉的是目前打開的專案 → 自動切到清單中的下一個專案；沒有下一個就切到上一個；都沒有就變成 `null`。

## 5. 畫面規格

### 5.1 版面

```
┌───────────────┬──────────────────────────────────┐
│  Stairs       │  寫論文  ✏️ 🗑️                    │
│               │  進度 2 / 5  ████████░░░░░░░      │
│ ▸ 寫論文      │                                   │
│   整理房間    │  ⋮⋮ ☑ 找題目            ✏️ 🗑️    │
│               │  ⋮⋮ ☑ 讀文獻            ✏️ 🗑️    │
│ [新專案名…]   │ ▌⋮⋮ ☐ 寫大綱      ↑ ↓   ✏️ 🗑️    │ ← 目前這一階
│ [＋ 新增]     │  ⋮⋮ 🔒 寫初稿      ↑ ↓   ✏️ 🗑️    │ ← 灰色
│               │  ⋮⋮ 🔒 修改        ↑ ↓   ✏️ 🗑️    │ ← 灰色
│               │                                   │
│               │  [新步驟…]  [＋ 新增]             │
└───────────────┴──────────────────────────────────┘
```

- 左邊：專案清單 + 新增專案輸入框。目前打開的專案要醒目標示。
- 右邊：專案名稱（可改名、刪除）、進度、步驟清單、新增步驟輸入框。
- 進度顯示「已完成數 / 總數」和一條進度條。
- **手機寬度（< 640px）**：改成上下排列，專案清單在上、步驟在下。按鈕觸控區至少 40×40px。

### 5.2 空狀態

- 沒有任何專案 → 右邊顯示：「還沒有專案。在左邊輸入名稱，建立你的第一個專案吧！」
- 專案沒有步驟 → 步驟區顯示：「這個專案還沒有步驟。在下面新增第一階。」

### 5.3 風格

- 介面文字一律**繁體中文**。
- 乾淨、簡單、留白充足。
- 支援**深色模式**，跟隨系統設定（`prefers-color-scheme`）。
- 顏色用 CSS 變數定義在 `:root`。
- 主色是**橘色**。淺色模式用米白底；深色模式用接近黑色的底。按鈕上的文字和背景要看得清楚（對比度至少 4.5:1）。
- **圖示用線條圖示**（自己畫的 SVG，不用 emoji、不用外部圖示庫）。本規格裡寫的 ⋮⋮、✏️、🗑️、🔒、↑、↓ 是指「這個位置有這個意思的按鈕或標示」，畫面上用對應的線條圖示呈現。慶祝彈窗標題的 🎉 保留 emoji。
- **步驟排成階梯狀**：越後面的步驟往右縮排越多，像一階一階的樓梯。縮排有上限，超過上限的步驟對齊在最右的那一階。手機寬度時每階縮排比較小，標題仍要有足夠寬度。
- 階梯狀不改變任何操作規則：順序、拖曳、↑↓、打勾都和 F2–F4 相同。
- **App 圖示**：黑底、橘色階梯（和畫面左上角 Stairs 旁邊的圖案相同）。用專案裡的一張 180×180 PNG，同時當瀏覽器分頁的小圖示和 iPhone「加入主畫面」的圖示，主畫面名稱是「Stairs」。
- **動畫**：操作後的畫面變化用短動畫（約 0.2 秒）呈現：排序時步驟滑到新位置、新增的步驟淡入、刪除的步驟淡出、打勾時勾勾彈一下、下一階解鎖時亮一下、進度條長長、彈窗淡入。
  - 系統開啟「減少動態效果」（`prefers-reduced-motion: reduce`）時，不播放這些動畫。
  - 瀏覽器不支援時沒有動畫，功能完全不受影響。
  - 動畫不能擋住操作：動畫進行中仍可以點按、打字；焦點規則和 §6 相同。

## 6. 無障礙

- 所有只有圖示的按鈕都要有 `aria-label`（例如「刪除步驟：找題目」）。
- 全部功能都能**只用鍵盤**操作（Tab、Enter、空白鍵、Esc；排序用 ↑↓ 按鈕）。
- 勾選框用真正的 `<input type="checkbox">` 或有正確 role 的元素。
- 鎖住的步驟：勾選框 `disabled`，並用 `aria-describedby` 或 `title` 說明「需先完成上一階」。
- 慶祝彈窗用 `role="dialog"`、`aria-modal="true"`，開啟時焦點移到「關閉」按鈕，關閉後焦點回到原本位置。

## 7. 資料操作函式介面

這些函式放在哪個檔案、怎麼讓畫面呼叫：見 `ARCHITECTURE.md`。

**規則：**
- 除了 `load` / `save`，全部是**純函式**：輸入舊 state，回傳**新的** state，**不修改**傳進來的物件。
- 每個函式做完，不變式（§3.2）都必須成立。
- 不合法的操作（找不到 id、勾鎖住的步驟、名稱空白、移到不允許的位置…）→ **直接回傳原本的 state**，不丟錯誤。

| 函式 | 說明 |
|---|---|
| `emptyState()` | 回傳空資料。 |
| `load()` | 從 localStorage 讀取並驗證／修正（§3.3），回傳 state。 |
| `save(state)` | 存進 localStorage。失敗時回傳 `false`，成功回傳 `true`。 |
| `createProject(state, name)` | 新增專案並設為 active。 |
| `renameProject(state, projectId, name)` | 改專案名。 |
| `deleteProject(state, projectId)` | 刪專案，並依 F7 規則調整 `activeProjectId`。 |
| `setActiveProject(state, projectId)` | 切換專案。 |
| `addStep(state, projectId, title)` | 在最後新增未完成步驟。 |
| `renameStep(state, projectId, stepId, title)` | 改步驟名。 |
| `deleteStep(state, projectId, stepId)` | 刪步驟。 |
| `moveStep(state, projectId, stepId, toIndex)` | 把未完成步驟移到 `toIndex`（移動後的位置）。已完成步驟或目標在已完成區 → 不變。 |
| `checkStep(state, projectId, stepId)` | 只有「目前這一階」能成功打勾。 |
| `uncheckStep(state, projectId, stepId)` | 取消該步驟和後面所有步驟。 |
| `getCurrentStepIndex(project)` | 回傳目前這一階的位置；沒有則回傳 `-1`。 |
| `countDone(project)` | 回傳已完成數。 |
| `isProjectComplete(project)` | 至少 1 步且全部完成 → `true`。 |

慶祝畫面的觸發由畫面程式判斷：`checkStep` 前 `isProjectComplete` 是 `false`、之後是 `true` → 顯示慶祝。這個狀態**不存檔**。

## 8. 驗收清單

全部打勾才算完成。每一項都要實際在瀏覽器操作過。

**基本**
- [ ] 雙擊 `index.html`，不用任何伺服器就能用。
- [ ] 斷網也能正常使用。
- [ ] 重新整理後，專案、步驟、完成狀態、目前打開的專案都還在。

**F1 專案**
- [ ] 能新增多個專案，新專案自動被打開。
- [ ] 能在專案間切換，各自的步驟和進度互不影響。
- [ ] 空白名稱無法新增。

**F2 步驟**
- [ ] 新步驟加在最後、未完成。
- [ ] 未完成步驟可以用滑鼠拖曳換順序。
- [ ] 手機（或瀏覽器觸控模擬）可以拖曳。
- [ ] 已完成步驟不能拖；未完成步驟拖不進已完成區。
- [ ] ↑↓ 按鈕可以排序，規則和拖曳相同。

**F3 / F4 鎖定與解鎖**
- [ ] 只有目前這一階能打勾。
- [ ] 後面的步驟是灰色、有 🔒、無法打勾。
- [ ] 打勾後，下一階立刻解鎖。

**F5 慶祝**
- [ ] 打勾最後一階時跳出慶祝畫面。
- [ ] 能用按鈕、Esc、點外面關閉。
- [ ] 重新整理或切換專案後不會再跳。
- [ ] 刪除步驟造成全部完成時不會跳。

**F6 取消打勾**
- [ ] 取消最後一個已完成步驟：直接取消，不確認。
- [ ] 取消較前面的步驟：跳確認，寫出會退回幾個；確定後它和後面全部變未完成。
- [ ] 確認視窗按取消：什麼都沒變。

**F7 改名與刪除**
- [ ] 專案和步驟都能改名；Esc 取消；空白不存。
- [ ] 能刪除步驟；刪掉目前這一階後，下一階變成目前這一階。
- [ ] 刪除專案會先確認；刪除後自動切到其他專案。

**穩定性**
- [ ] 在 DevTools 把 `localStorage["stairs.v1"]` 改成亂碼，重新整理不會當掉。
- [ ] 手動把資料改成 `✓ □ ✓`，重新整理後自動修正成 `✓ □ □`。
- [ ] 手機寬度版面正常，沒有橫向捲軸。
- [ ] 深色模式顯示正常。
- [ ] 只用鍵盤可以完成所有操作。
